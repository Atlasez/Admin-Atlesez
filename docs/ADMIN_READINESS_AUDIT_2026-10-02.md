# Atlasez 運営開始に向けた実運用監査

調査日：2026年10月2日（日本時間）。最終SHA照合：16:45 JST。

## 判断

参加申込み、Googleログイン、プロジェクト別権限、タスク、カレンダー、原稿編集、公開処理、Discord連携、通知、監査、休止・退会申請などの土台はある。ただし、本番がGitHub mainの改修を配信できていないこと、応募フォームの表示不具合、公開側の個人情報説明の不足、新規参加者の実サービスを通した受入検証が残っている。この状態で広く一般募集を始めることは勧めない。

まずP0を完了し、5〜10人で試験運用する。これは監査上の提案であり、現在の運用規模や決定済み方針を示すものではない。P1は一般募集前に実際の募集範囲に応じて完了させ、P2は利用結果を見て進める。

## 直接確認したこと

1. **本番とmainのSHA不一致**。本番は74084dc6147490fef228b6a1f68ae3fedae79ba7、builtAtは2026-09-29T10:57:48.705Z。最新mainの本番同期Workflowも失敗した。問題は単なる画面のキャッシュと断定できず、Workers Builds接続復旧が必要。[本番情報](https://admin.atlasez.org/build-info.json) / [失敗した同期検証](https://github.com/Atlasez/Admin-Atlesez/actions/runs/36978168138)
2. **診断が実際の配信状態を保証していない**。開発者画面は旧SHAでも「配信ビルド情報：正常」。mainの実装ではbuild-info取得の成否だけを判定し、定期処理・Previewも固定文言で正常とする。スキーマ確認も3テーブルのみ。[診断画面](https://admin.atlasez.org/admin/developer/) / [実装](https://github.com/Atlasez/Admin-Atlesez/blob/743ab214fe525e0aea0809b8ab36218156e93c34/src/admin-worker.ts#L2913)
3. **応募フォームの別プロジェクト設問が見えている**。考えるカフェ応募画面に、生徒会・運営事務局向けの設問まで表示。DOMでは該当領域にhidden属性があるのにcomputed displayがgrid、表示領域も存在した。mainにも.project-extraのdisplay:gridとhidden時の保護不足が残る。見た目を直すだけでなく、不要項目のrequired・送信対象も確認する。[応募画面](https://admin.atlasez.org/apply/thinking-cafe/) / [実装](https://github.com/Atlasez/Admin-Atlesez/blob/743ab214fe525e0aea0809b8ab36218156e93c34/src/pages/apply/index.astro#L84)
4. **公開プライバシーポリシーに応募情報の取得・保管説明がない**。フォーム内に説明はあるが、公開ページはお問い合わせ情報と外部サービス等の旧内容。ADMIN mainの改善を公開側の正本へ反映する必要がある。公開リポジトリmain自体も旧内容だったため、ADMINの配信復旧だけで解決すると考えない。[公開ポリシー](https://atlasez.org/privacy-policy/) / [公開側の正本](https://github.com/Atlasez/Atlasez01/blob/17abea4ed6eeb97719dee60f57bc6b26d5d2d53a/src/pages/privacy-policy.astro)
5. **募集ページの応募ボタンはアトラスへの1本**。ADMIN mainには5プロジェクトの入口があるが、公開中のjoinにはapply/atlasへのボタンのみ。ゼミ紹介からも運営募集へ戻る導線だった。募集対象が複数ならプロジェクトを選んで応募できる導線を公開側で整える。[募集ページ](https://atlasez.org/join/)
6. **応募用Turnstile公開キーは未設定**。公開application-configでsiteKeyConfigured=false。サーバー側の秘密キー設定状況は今回確認していない。main実装では秘密キーがある場合にだけ検証する。既存のGoogle認証・IP回数制限・重複応募拒否はあるため「無防備」と断定しない。[設定API](https://admin.atlasez.org/api/public/application-config) / [検証実装](https://github.com/Atlasez/Admin-Atlesez/blob/743ab214fe525e0aea0809b8ab36218156e93c34/src/admin-worker.ts#L13971)
7. **本番にテスト作業が残っている**。ポータルの未完了タスクにaaaaaaと公開後削除予定の表示テスト依頼がある。応募側とADMIN側で同じアカウントの表示名が異なる例もあった。まず元データと用途を確認し、実作業から分離する。自動削除は行わない。[ポータル](https://admin.atlasez.org/admin/portal/)
8. **公開処理に要確認27件、公開済み処理14件と表示**。これは処理履歴の件数で、現在の障害件数や公開記事数ではない。8〜9月のテスト記事や過去のCI失敗、設定エラーが多い。履歴を残しながら、解決済み・再対応必要・テストに整理する。[公開処理](https://admin.atlasez.org/admin/publication-runs/)
9. **未認証アクセスの基本境界は動作**。portal、member-tasks、member-calendar、profile、editor/documentsの5 APIはすべて401 JSONを返した。別プロジェクトの会員、応募者、退会者などの認証済み権限境界は別途確認が必要。

## 既存記録から分かったこと

[Issue #407](https://github.com/Atlasez/Admin-Atlesez/issues/407)の10月2日の記録では、Workers Builds接続時の自動トークン作成がAccount Settings Readの権限チェックで拒否されている。現在のユーザーの役割はDNS, Workers Platform Adminと記録されている。既に原因が特定されているため、同じフォームを繰り返し送ることを対策にしない。必要権限を持つ担当者による、レビュー済みの同じ接続設定での復旧が第一候補。別トークン構成へ変える場合は、設定・影響・復旧方法を別途レビューする。[Cloudflare公式Builds設定](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)

同IssueにはD1 0120〜0123適用成功、未適用0、外部キー不整合0、直前バックアップのローカル保管・復元検証成功が記録されている。追加migrationが未適用と決めつけたり、再適用や逆migrationを行ったりする必要はない。本番コードを反映した後、互換性と主要操作を再確認する。

9月30日の復元記録は75テーブル、integrity_check=ok、foreign_key_check=0。復元検証と手順は既にある。継続的な保管、復旧担当者、保持期間、復旧目標と、隔離環境での再訓練を整えることが残る。[復旧文書](https://github.com/Atlasez/Admin-Atlesez/blob/743ab214fe525e0aea0809b8ab36218156e93c34/docs/ADMIN_D1_RECOVERY.md) / [Cloudflare Time Travel公式仕様](https://developers.cloudflare.com/d1/reference/time-travel/)

## 試験運用の開始・終了条件（提案）

開始前には、P0の8項目を完了させる。既存の検証済み事項は証拠を確認して再利用し、不要な再実装はしない。参加者全員に一般募集前の試験運用であることと連絡先を説明する。

5〜10人で、一般会員・担当者・レビュアー・管理者を含め、可能なら2プロジェクトで試す。新規参加→最初の小タスク→質問→レビュー→成果物公開/イベント実施までを通す。検証に用いる個人情報・原稿は管理されたものに限定する。

一般募集へ進む条件は、権限逸脱とデータ消失を起こさず、応募/通知/公開/退会を担当者が処理でき、未処理に担当が付き、初参加者が最初の作業を完了できること。運営者がいる時間以外の障害や連携停止でも、誰が何をするか決まっていること。P1の未完了項目は募集範囲に対する影響と回避方法を明記する。

## 今回の監査で新規実装しないもの

タスク・カレンダー・通知・応募管理・休止/退会・監査ログ・操作検索・テンプレート・運営統計を、存在しない機能として再提案しない。mainにある改修はまず本番反映して利用を確かめる。管理者向け画面が表示できることだけで、一般会員の安全性や通知到達を完了にしない。

macOSの起動不具合は1.0.4で修正した既存成果として扱う。Apple Developer契約、署名・公証は以前の指示で今回対象外であり、この監査の必須作業には入れていない。

今回行ったのは調査と一覧の作成。本番設定、応募データ、権限、原稿、リポジトリのコードは変更していない。
