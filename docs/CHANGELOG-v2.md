## v2.1 アクセシビリティ修正（CI の axe 検査対応）

初回 CI で `atlas/ja/` と `atlas/en/` の axe 検査が落ちました。原因と対応：

- **`opacity: 0.72` によるコントラスト不足（WCAG 1.4.3, 違反）**
  準備中の分野タイルを `opacity` で淡くしていたため、白背景との実効コントラストが
  分野名 2.88:1 / 「準備中」ラベル 3.36:1 まで落ちていました（要求 4.5:1）。
  `opacity` を廃止し、色は `--text-secondary`（6.34:1）のまま、
  **文字の太さ（500 対 650）と下線の破線化**で公開／準備中を区別する方式に変更。
- **「?」ボタンのターゲットサイズ不足（WCAG 2.5.8, 違反）**
  1.35rem = 21.6px で 24px 未満でした。1.5rem（min 24px）に拡大。
- **分野名リンクのターゲットサイズ（予防的対応）**
  インライン要素で高さが 24px 前後と際どかったため、`inline-flex` + `min-height: 1.75rem` に。
- **「最近更新された記事」の日付の色**を `--text-muted` → `--text-secondary` に変更。
  `--text-muted` は既定の白背景では 4.93:1 で通りますが、表示設定の「低刺激色」背景では
  4.45:1 と基準割れするため。

検証：axe-core を jsdom 上で実行し構造ルールは 0 件、コントラストは各配色の

## v2.3 Cloudflare Pages への配信切り替え

配信先を GitHub Pages から Cloudflare Pages に移した。

- **`astro.config.mjs`**: `SITE_URL` → `CF_PAGES_URL` → `http://localhost:4321`
  の順にフォールバック。`SITE_URL` を Production 環境にだけ設定すれば、
  プレビュー配信は自分自身の URL を canonical に使う。
  既定値だった `https://atlasez.github.io` は誤ったURLが本番に出る事故のもとなので撤去
- **プレビュー配信の noindex 化**（`src/lib/deploy.ts`）。`CF_PAGES_BRANCH` が
  `main` 以外なら全ページに `noindex, nofollow` を付け、`robots.txt` も
  `Disallow: /` にする。本番と同じ内容が二重にインデックスされるのを防ぐ
- **`robots.txt` を動的生成に変更**（`public/robots.txt` → `src/pages/robots.txt.ts`）。
  従来は sitemap の URL が GitHub Pages のものにハードコードされていた
- **`public/_headers` を追加**。`nosniff` / `Referrer-Policy` /
  `X-Frame-Options` / `Permissions-Policy` / `Cross-Origin-Opener-Policy` と、
  `/_astro/*` の 1 年 immutable キャッシュなど
- **`.nvmrc`（22）を追加**。Cloudflare Pages と GitHub Actions で
  Node のバージョンを 1 箇所から与えるため。ci.yml も `node-version-file` に変更
- **`ci.yml` の deploy ジョブを削除**。GitHub Actions は検証専用になった。
  あわせて検証時の `BASE_PATH` を `/<リポジトリ名>` から `/` に変更し、

## v2.4 漢字記事の一字表の組み直し

「読みがずれている・空きがある」というご指摘への対応。

**原因**：元データ（Google Sites）の表は読みのセルが**縦に結合**されていた。
Markdown へ変換した際に

1. 先頭の実データ行がそのまま Markdown のヘッダ行になり、
   1 文字目の漢字が列見出しとして描画されていた
   （例: 「火 | ひ | ほ」が表のヘッダになっていた）
2. 結合セルだった箇所が空セルや欠けた列として残り、表に穴が空いていた
   （例: `| 燬 |  |` `| 焔 |`）

**対応**：`scripts/fix-kanji-tables.mjs` を追加し、結合セルの意味どおりに
読みを上の行から引き継いで 2 列（漢字・読み）の表に組み直した。

```
| 火 | ひ | ほ |        →   | 漢字 | 読み   |
| --- | --- | --- |         | ---- | ------ |
| 燬 |  |                   | 火   | ひ、ほ |
| 炎 | ほのお |              | 燬   | ひ、ほ |
| 焔 |                      | 炎   | ほのお |
                            | 焔   | ほのお |
```

- 対象は漢字記事 78 件のうち 77 件・表 278 個
  （`nature/sky.md` だけ以前に手で直されていたので対象外）
- 複数列に分かれていた読みは「、」で連結（セル内では「・」が使われているため）
- 変換済みの表は触らないので、スクリプトは何度実行してもよい

**検証**

- 元データの漢字セル 1916 個と変換後の行 1916 行が一致（欠落ゼロ）
- 元データから前方補完で作った期待値 1916 組と、変換後の（漢字, 読み）が**完全一致**
- 読みが空のまま残った行 0 件

## v2.5 数式・記事構造・概念グラフの一括修正

### 1. 数式内の日本語（KaTeX 警告 78 → 0）

KaTeX は数式モードの文字を数式用フォントの斜体で組むため、`(Tは定数)` や
`x=x'かつy=y'` のように日本語を生で書くと字形も字間も崩れていた。

- `scripts/fix-math-japanese.mjs` を追加。数式を走査し、`\text{}` の外にある
  日本語を `\text{}` で包む（4 ファイル・15 箇所）
- `\mathrm{個}` `\mathrm{u/個}` は `\mathrm` が数式モードのままなので
  `\text{個}` `\mathrm{u}/\text{個}` に修正
- KaTeX が CJK に付ける `.cjk_fallback` クラスに本文フォントを当てる CSS を追加。
  既定のままだと本文と字形・字幅が揃わないため

### 2. 漢字記事の余白・空見出し（`scripts/tidy-kanji-articles.mjs`）

- 中身のない `#### 【熟語】` 見出し **117 個**を削除。
  見出しだけが残って記事に穴が空いて見えていた
- セクション区切りの水平線 `---` を **201 本**削除。
  `### 見出し` で十分区切られており、上下余白が積み重なって間延びしていた
- 熟語欄の空白区切り 7 箇所を「・」に統一

熟語が区切りなしで連結されている箇所（「炎炎炎焼炎上火炎」など）は、
元データにも区切りがなく偶数長も 23% しかないため機械的に分割できない。手つかず。
