# 執筆・査読・公開フロー

この文書は、現在の学習サイト運営用サイトで行う記事作業の流れをまとめたものです。画面操作の詳しい説明は [ADMIN_GUIDE.md](ADMIN_GUIDE.md)、記事データの形式は [CONTENT_MODEL.md](CONTENT_MODEL.md) を参照してください。

## 1. 原稿を選ぶ

`/admin/articles/` を開き、タイトル・分野・カテゴリ・原稿状態・公開状態で絞り込みます。

- **新規記事作成**: 新しい下書きを作る。
- **加筆・修正**: 自分が関わった原稿を優先して探す。
- **査読待ち**: 全分野管理者だけが使える査読用の絞り込み。

カード全体から編集画面へ移動できます。既存の公開記事を修正する場合も、編集画面の「学習サイトに公開済みの記事を編集」から取り込みます。

## 2. 下書きを保存する

本文とWebプレビューを並べて確認し、記事設定（分野・カテゴリ・slug・言語・LaTeXエンジン）を確認して **保存する** を押します。言語の保存ディレクトリはISO 639-3形式です（日本語 `jpn`、英語 `eng`）。保存中・自動保存済み・保存失敗は画面上部に表示されます。

## 3. 査読を依頼する

執筆者が内容を整えたら **査読を依頼する** を押します。依頼は運営内運営へ通知され、原稿は査読中になります。査読は匿名ではなく、査読依頼の一覧とコメント欄には依頼者・査読者の表示名が表示されます。

査読者は本文を範囲選択してコメントし、「定義不足」「誤字」「脱字」などのタグ、引用、返信、メンションを使って修正点を伝えます。コメントの確認済み・未反映などの状態もスレッドに残ります。

## 4. 査読を完了する

全分野管理者がコメントと本文を確認します。修正が必要ならコメントで差し戻し、判断を保留する場合は理由を残します。内容が整ったら管理者が査読完了にします。執筆者には査読完了の通知が届きます。

## 5. 公開する

査読完了後、全分野管理者だけに **公開する** が表示されます。確認ダイアログで実行すると、公開サイトの同じ記事URLを更新するビルド・デプロイが開始されます。反映には数十秒から数分かかるため、すぐに見えない場合は少し待ってから再読み込みします。公開時には執筆者へ通知されます。

公開後に修正が必要になった場合は **公開を取り消す** で下書きへ戻し、改訂後に再査読します。

## 6. GitHubとの関係

GitHubはコード・記事本文・翻訳データの変更履歴とPull Requestの確認に使います。日常の下書き・コメント・査読・参加者情報は管理Worker + D1に保存します。秘密情報をリポジトリへ置かず、GitHubの差分には個人情報やOAuthトークンを含めません。

CIでは型チェック、lint、単体テスト、コンテンツ検証、リンク検証、ビルドなどを実行します。失敗した場合はエラーログを確認してから修正し、Cloudflareの本番デプロイを手動で回避しないでください。
