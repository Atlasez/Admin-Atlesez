# Atlasez運営サイトの使い方

この文書は、現在の運営サイトを初めて使う人向けの実務ガイドです。画面上の「作業の進め方」からも同じ内容を確認できます。古いGoogle Sitesの手順やGitHubだけで公開する手順ではなく、現在のCloudflare Worker + D1の運営サイトを基準にしています。

## 1. サイトの入口

| 用途 | URL |
| --- | --- |
| メンバー用ホーム（参加プロジェクト・横断ToDo） | `/admin/portal/` |
| 学習サイト「アトラス」運営用ホーム | `/admin/atlas/` |
| 編集・査読一覧 | `/admin/articles/` |
| 原稿編集画面 | `/admin/editor/` |
| 進捗・ToDo・日程 | `/admin/operations/` |
| 問題報告・閲覧統計 | `/admin/reports/` |
| 運営用ガイド | `/admin/guide/` |

本番では `https://atlasez-admin.ukyoukay0.workers.dev` の後ろに上記パスを付けます。学習者向けサイトは `https://atlasez-web-1.ukyoukay0.workers.dev/atlas/ja/` です。ロゴはそれぞれのホームへ戻るリンクで、パンくずは現在地と一つ上の場所を示します。

## 2. ログインと権限

Googleアカウントでログインします。運営サイトのセッションはCloudflare Workerで管理され、未ログインの人は管理画面へ入れません。運営参加応募フォームだけはログイン不要です。

- **分野担当**: 自分に割り当てられた分野の原稿・コメント・作業を扱います。
- **全分野管理者**: 分野担当の割り当て、応募の承認、Discordロール同期、査読完了、公開、公開取消を扱います。
- 査読は運営側で匿名に行います。査読担当者のメールアドレスを記事執筆者へ表示する運用ではありません。

画面でボタンが見えない場合でも、URLを直接開けば使えるとは限りません。重要な権限はWorker側でも検査しています。権限変更は「管理」→「運営者・担当管理」から全分野管理者だけが行います。

## 3. 記事を作成・修正・公開する

### 3.1 編集・査読一覧

「編集・査読」では、タイトル・分野・カテゴリの検索、原稿状態、公開状態、テスト原稿の絞り込みができます。

- **新規記事作成**: 空の原稿を作成して編集画面を開く。
- **加筆・修正**: 自分が関わった原稿を優先して表示する。
- **査読待ち**: 全分野管理者だけに表示され、査読が必要な原稿を優先して表示する。

一覧カード全体を押すと編集画面へ移動できます。タイトルが同じ記事は分野・カテゴリ・slugで区別し、同じ原稿を編集するたびに複製する必要はありません。

### 3.2 編集画面

編集画面では本文、Webプレビュー、執筆メモ、コメント、版履歴を切り替えます。本文を保存する前にページを移動すると警告が出ます。自動保存の状態は画面上部で確認できます。

1. Markdown本文とプレビューを確認する。
2. 「記事設定」を開き、分野・カテゴリ・slug・言語などを確認する。リポジトリ上の言語ディレクトリはISO 639-3（日本語 `jpn`、英語 `eng`）を使う。
3. **保存する**で下書きを保存する。
4. 執筆者が作業を終えたら**査読を依頼する**。コメント欄では範囲選択、タグ、返信、メンションを使える。
5. 査読後、全分野管理者が査読結果を確認し、必要なら保留・修正依頼にする。査読完了にすると公開操作へ進める。
6. 全分野管理者だけが**公開する**を押し、確認ダイアログで実行する。公開後、学習サイトへの反映には数十秒から数分かかる。
7. 誤りが見つかった場合は**公開を取り消す**で下書きに戻し、修正して再度査読する。

「原稿状態（下書き・査読中・査読済み）」と「公開状態（未公開・公開済み）」は別に表示されます。公開済みでも原稿状態が査読済みと表示されるのは正常です。

### 3.3 数式とプレビュー

WebプレビューはKaTeX（高速）またはMathJax（互換性重視）を選択できます。原稿のLaTeXコンパイル形式は upLaTeX / pdfLaTeX / XeLaTeX / LuaLaTeX から記事設定で選びます。プレビュー用の組版方式と、PDFを作る場合のLaTeXエンジンは別の設定です。本文に `script` タグを追加する必要はありません。

## 4. コメント・査読

本文をドラッグして範囲を選び、コメントを追加します。「定義不足」「誤字」「脱字」などのタグだけでも送信できます。返信にもタグと引用を付けられ、`@` を入力するとメンバー候補が表示されます。コメントの解決・未反映・確認済みの状態は、対応状況を共有するために使います。

査読依頼や自分の記事へのコメント、返信、公開・査読完了は右上のベルに届きます。未読数は赤い数字で表示され、既読にすると未読数から消えますが、通知履歴自体は残ります。

## 5. 進捗・ToDo・日程

「進捗・ToDo・日程」では、自分が担当するToDo、自分が依頼したToDo、自分が送った進捗報告を切り替えて確認できます。期限順、期限切れ、今日まで、担当者、依頼者で絞り込み、期限日時・タイムゾーン・繰り返しリマインダーを設定します。

進捗報告を保存すると、設定済みのDiscord分野チャンネルと全体進捗チャンネルへ自動通知されます。日程調整では地域別タイムゾーン、予定、参加可否を登録できます。カレンダーは外部カレンダーサービスではなく、D1の予定データとブラウザの日時フォーマットで表示します。

## 6. 参加者・応募・Discord

運営参加応募はログイン不要で、氏名（姓・名・ふりがな、英語名のmiddle nameは任意）、所属区分、学校・研究機関、学年、タイムゾーン、関心分野を入力します。候補にない学校は自由入力でき、承認時に運営側が確認します。興味分野に上限はありません。

応募の承認、所属・学年・担当分野の変更、DiscordユーザーIDの登録、ロール同期は全分野管理者だけが行います。参加者カードには表示名・アイコン・所属・学年・担当分野を表示し、メールアドレスやDiscord IDは必要な管理者だけに表示します。Discordロール同期は参加者カードの「変更を保存してDiscordロールを同期」で実行し、未作成ロールは必要に応じて作成・記録します。

## 7. 問題報告と個人情報

問題報告は学習サイトの記事から送信し、運営サイトの「問題報告・閲覧統計」で確認します。記事の分野に応じたDiscordチャンネルへ通知されます。メールやDiscordのWebhook、OAuth秘密鍵、D1の認証情報はGitへ保存しません。退任者の権限を削除し、プロフィール画像や応募情報を必要以上に公開しないでください。

## 8. 困ったとき

- 「読み込み中」のままなら、まずページを再読み込みし、Googleアカウントのログイン状態を確認する。
- `Unexpected token '<'` や `Unexpected end of JSON` が出たら、APIがHTMLエラーページを返していないかを確認し、再ログインして再試行する。
- 権限がない場合は、画面を迂回せず全分野管理者へ依頼する。
- 公開後の反映はすぐでない場合がある。数分待ってから学習サイトの同じURLを再確認する。
- それでも直らない場合は、記事URL、発生時刻、操作、画面のエラー文を問題報告へ残す。アクセストークンや個人情報は貼らない。

## 9. 開発者向け補足

運営UIは `src/pages/admin/`、管理API・認証・D1処理は `src/admin-worker.ts`、公開学習サイトと公開APIは `src/worker.ts` にあります。運営用D1のスキーマは `migrations/` を順番に適用します。日常の確認は次のコマンドで行います。

```bash
npm ci
npm run check
npm run lint
npm test
npm run build
npx wrangler d1 migrations apply atlasez-reports-local --local --config wrangler.admin.local.jsonc
npm run dev:admin
```

構成やデプロイの詳細は [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md)、リポジトリ境界は [REPOSITORY_BOUNDARIES.md](REPOSITORY_BOUNDARIES.md)、記事データの形式は [CONTENT_MODEL.md](CONTENT_MODEL.md) を参照してください。
