# タスクテンプレート・定期作成・通知設定

## 対象と動作

- `/admin/task-templates/` に本人所有のテンプレートを追加。参加中プロジェクトだけを対象とし、一般メンバーの担当者は本人に限定する。運営は同じプロジェクトのメンバーを指定できる。最大100件。
- 手動作成はリクエストIDで重複を防ぐ。定期作成は日・週・月の周期とタイムゾーンを指定し、既存の5分・毎時Cronから最大25件ずつ処理する。CloudflareのCron設定を変更しない。
- 同時実行時もタスク作成と次回日時更新をD1 batchでまとめる。作成時に所属・権限を再確認し、失効時は定期作成を停止する。
- 月末は元の開始日に基づき、1月31日→2月末→3月31日と進む。夏時間で存在しない／曖昧な開始日時は受け付けず、次回計算時の該当日は飛ばす。停止期間に複数回分が積まれた場合は1件作成して次の未来の周期へ進む。
- 期限は任意。指定した場合は作成予定日時から指定タイムゾーンの暦日で計算する。
- `/admin/notifications/` に表示中の通知の要約、重要な通知の絞り込み、種類別表示設定、1時間後の再表示と予約解除を追加。設定は本人だけに適用し、既読状態とメール送信設定は変更しない。
- 非表示・再表示予約の条件はSQLの表示上限と件数集計の前に適用する。

## データと適用順

本番migrationは未適用。既存のADMIN D1に対しレビュー後に以下の順で適用する。

1. `0120_publication_review_started_at.sql`（統計改善PR #481を先に導入する場合）
2. `0121_editorial_task_templates.sql`
3. `0122_admin_notification_preferences.sql`
4. CIとレビューが完了したmainをWorkers Buildsから反映。

0121はテンプレート、0122は本人の通知設定・再表示予約の新規テーブルだけを作成し、既存行を更新しない。0121未適用時は定期作成をスキップしてAPIは503を返す。0122未適用時は従来の通知一覧を表示して設定操作を無効にする。0122内の2テーブルを両方適用してから新しい通知設定を利用する。

Worker名・Route・Bindings・Durable Object・公開サイトAPIは変更しない。既存の認証範囲から本人と所属を解決し、新規のメンバー用APIだけを許可する。

## 検証と復旧

単体テストは同時Cron、手動リトライ、権限失効、別人のテンプレート、月末と夏時間、通知フィルター205件、再表示期限と本人への設定限定をSQLiteで確認する。E2Eは保存エラー後の復帰、連打、モバイル表示、通知の絞り込み・再表示・設定保存を確認する。

本番反映後は認証済みChromeで上記画面と既存ポータル・タスク・カレンダー・マイページを確認する。migration不足、CI失敗、SHA不一致があれば停止する。

問題発生時はテンプレートを停止し、レビューされたmainで機能を戻す。新規テーブルと作成済みタスクを保持し、自動削除・破壊的rollbackを行わない。旧Workerへ戻した場合は定期作成処理がなくなるため生成は停止する。D1復旧が必要な場合は `ADMIN_D1_RECOVERY.md` の確認済み手順を使う。
