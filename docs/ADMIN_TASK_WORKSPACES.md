# タスク詳細・引き継ぎ

## 画面と権限

横断タスクの「詳細・引き継ぎ」から `/admin/task-detail/?task=<ID>` を開く。
現在の状況、次にすること、判断・対応待ち、関連原稿、確認項目、同じプロジェクトの前提タスクを保存できる。
確認項目は30件、前提タスクは20件まで。前提タスクは待ち状態を表示する補助情報であり、既存の状態遷移を禁止する条件にはしない。

閲覧範囲は横断タスク一覧と同じプロジェクト・担当分野・本人の担当/依頼範囲。
編集は担当者・依頼者・プロジェクトの運営内運営。担当変更は運営内運営だけで、参加中の担当者を選択し、現在の状況と次にすることを引き継ぎ履歴へ残す。
履歴は直近20件を表示し、削除APIを設けない。一般メンバーの応答に他人のメールアドレスを含めない。
関連原稿も記事の閲覧権限で確認する。参照先の権限が失われた場合は名前・IDを返さず、詳細画面を閲覧専用にして参照を誤って削除しない。

マイページには `/api/admin/my-access` が認証中の本人の担当分野・参加プロジェクト・管理役割を返す。
応募段階の利用者にはメンバー権限を付与しない。権限一覧の個人設定では、保存前の担当権限の追加・解除案を表示する。Discord同期後の権限は既存の「実効権限」で確認する。

運営統計から未完了・期限超過のタスク一覧へ移動できる。リンクのプロジェクト・状態・期限条件を初回API取得から適用し、権限の可視範囲は従来どおり維持する。

## 同時編集と監査

保存はタスクの更新時刻とワークスペースのrevisionを照合し、DB更新時にも両方を検査する。
前提の循環は読み取り時と更新SQLの両方で検査する。D1 batchで担当変更・メモ・履歴・監査を同一トランザクションにし、監査失敗時も担当変更を残さない。
古い編集は409となり、画面の入力は保持する。保存待ちに追加入力した内容も未保存のまま保持する。

## D1と適用順

`0123_task_workspaces.sql` は2つの新規テーブルと索引だけを追加する。既存の行を更新・削除しない。
#481/#482を先に導入する場合は0120→0121→0122→0123の順でレビューし、バックアップ後に適用する。0123自体は他の新機能テーブルに依存しない。
本番migrationはPRレビュー後に正本D1へ適用し、その後レビュー済みmainをWorkers Buildsで反映する。
migrationがない場合、新APIは503となる。タスクの既存一覧・作成・状態変更は利用できる。

## 検証と復旧

SQLiteで実SQLの担当変更、循環、他プロジェクト拒否、競合、監査失敗時のロールバックを検証する。
画面では保存失敗・追加入力保護・閲覧専用・390px幅・ダーク表示を確認する。
反映後はタスク詳細とマイページ、およびポータル・タスク・カレンダー・管理トップ・記事一覧を認証済みChromeで確認する。
問題時はレビュー済みrevert commitをmainのWorkers Buildsで反映し、新規テーブルと引き継ぎ履歴は残す。DB restoreや破壊的な逆migrationは行わない。
CI失敗、migration不足、Worker/Version/SHA不一致、Workers Builds未接続の場合は本番反映を停止する。
