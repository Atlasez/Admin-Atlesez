# 運営サイト改善用プロンプト

```text
運営サイト全体を調査し、既存の権限境界・保存・公開処理を壊さずに、記事作成を「目次を先に設計し、その項目から本文を執筆する」流れへ統一する。

必須要件:
- 記事編集ワークスペースには原稿一覧の左サイドバーを追加しない。原稿一覧は編集・フィードバック、目次は独立した目次ページで扱う。
- 分野、カテゴリ、目次項目を運営画面から追加・編集・アーカイブできるようにする。
- 目次項目はタイトル、URL名、表示順、要約、概念IDを保持し、記事が未作成でも「未着手」として表示する。
- 目次項目の「執筆を開始」から、分野・カテゴリ・URL名・タイトル・要約・概念IDを引き継いだ新規原稿を開けるようにする。
- 作成済み原稿、公開済み記事、執筆中、アーカイブを同じ項目上で区別する。
- APIで担当外の分野を返さず、追加・編集・アーカイブにも同じ権限境界を適用する。
- 既存の学習地図・概念参照・公開PRの仕組みと互換性を保つ。概念IDやslugを利用者に手入力させる場合は、候補選択と自動生成を優先する。
- 既存ページの日本語UI、色、余白、コントロール高さに合わせ、英語の補助見出しや新しい装飾を追加しない。
- API変更にはマイグレーション、監査ログ、入力検証、重複防止を追加する。

検証:
- 記事編集画面に左サイドバーが表示されないこと。
- 独立した目次ページで担当範囲だけを閲覧できること。
- 目次項目の追加から記事編集への引き継ぎが機能すること。
- 本文、プレビュー、コメント、メモ、別窓、共同編集、公開処理の回帰がないこと。
- Unit、E2E、Lint、Buildを実行し、Chromeで画面を確認すること。
```
