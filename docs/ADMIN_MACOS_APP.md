# Atlasez運営 macOSアプリ

## 方針

このmacOSアプリは、Webサイトを枠に入れて見せるだけのランチャーではなく、SwiftUIのネイティブな業務ワークスペースとして段階的に移行する。データ・認証・権限判定は既存の `admin.atlasez.org` APIを正本として再利用し、アプリ側に権限ルールや業務状態の別コピーを作らない。WebViewは、未移行の高度な機能を使えるようにする互換層として残し、機能ごとにネイティブ画面へ置き換える。

オフライン専用製品への変更ではない。サーバー同期が必要な運営業務はネット接続を前提とする。

## 認証

- Google OAuthはアプリ内WebViewで実行せず、既定ブラウザで行う。アプリは先に127.0.0.1だけにbindした一時ポートのcallback listenerを起動する。
- WorkerはGoogleログイン後に2分で期限切れになる一回限りのPKCE認可コードを発行する。
- アプリはコードをWorkerへ交換し、短期セッションをKeychainへ保存する。WorkerのD1には既存と同じくセッショントークンのハッシュだけを保存する。
- アプリ内WebViewにはSecure/HttpOnly Cookieとしてセッションを渡す。通常のWeb/API権限チェックとログアウト処理は既存Workerを利用する。
- 新しいOAuthクライアントシークレットはアプリへ埋め込まない。

## ビルド

macOS上でUniversal（Apple Silicon / Intel）アプリとDMGを生成する。

```bash
npm run build:admin:dmg
```

出力先は `dist-macos/Atlasez-Admin.dmg`。配布時にGatekeeper警告をなくすには、Developer ID署名とApple公証が別途必要。

## 要件と制約

- macOS 13以降、Apple Silicon / Intelに対応。
- ネイティブ化済み: 運営ホーム（作業件数、担当タスク、予定、参加プロジェクト）と「要対応」（検索、期限・承認フィルター、完了履歴、既存状態遷移APIを使った承認・状態更新）。
- Web互換表示: 記事・フィードバック、タスク詳細・編集、カレンダー詳細、管理・権限、応募など、まだネイティブ移行していないページ。共同編集、記事プレビュー、メディア、公開審査などを壊さず使えるようにする暫定経路である。
- 左サイドバーからホーム、要対応、記事・フィードバック、タスク、カレンダー、管理へ移動できる。サイドバーはドラッグで幅を調整でき、アイコンだけの幅にも折りたためる。幅と折りたたみ状態はこのMacに保存される。
- ネイティブ画面は既存の `/api/admin/portal`、`/api/admin/action-center`、`/api/admin/workflow/transition` を使う。API応答を権限と件数の正本として扱い、各更新はサーバー側の認証、権限、状態競合チェックを経由する。拒否操作はアプリ上で確認を取る。
- 残るWeb互換表示は完成扱いにしない。次の移行対象はタスク・カレンダー、通知・プロフィール、運営管理、最後に共同編集を含む記事ワークスペースとし、各機能のAPI・権限・保存・テストを揃えてから置き換える。
- Google OAuthの後、Workerはアプリが提示した `http://127.0.0.1:<ephemeral-port>/callback` に短命の認可コードを返す。アプリ独自URLスキームを使わず、PKCE verifierの一致を確認して一度だけ交換する。
- アプリのログアウトはWorker上のセッションを失効させ、KeychainとWebKit Cookieを消去する。

## アプリ画面の移行状況

| 業務領域                             | 現在の表示        | 移行条件                                                                        |
| ------------------------------------ | ----------------- | ------------------------------------------------------------------------------- |
| 運営ホーム                           | SwiftUIネイティブ | Portal APIの同一権限範囲・件数を維持                                            |
| 要対応                               | SwiftUIネイティブ | 状態遷移API、競合検出、却下確認を維持                                           |
| タスク・カレンダー                   | Web互換表示       | 担当・期限・更新・ページング等の全操作をAPI経由で再現                           |
| 通知・プロフィール・応募・管理・権限 | Web互換表示       | 各画面のロール境界・監査・承認処理を同等にする                                  |
| 記事・フィードバック・共同編集       | Web互換表示       | Yjs同期、プレビュー、コメント、メディア、公開ワークフローを含む回帰テストが必要 |

この表は機能を隠すためではなく、ネイティブ実装の未完了範囲を明示するために使う。ネイティブ移行時も、既存Web画面を残したまま権限やデータの別実装を作らない。

Worker変更の本番利用には、migration `0119_admin_native_app_auth.sql` の適用と、GitHub `main`からの正規Workers Buildsデプロイが必要。手動・ローカルから本番deployしない。
